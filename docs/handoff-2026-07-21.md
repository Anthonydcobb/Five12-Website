## Environment — read before touching anything

**The single biggest time sink this session was a stale backend, twice.**

1. Python is `backend/.venv/Scripts/python.exe`. It has scapy, puresnmp and
   pytest. A bare `python` off PATH does not, and produces a misleading
   "puresnmp not installed" warning.
2. Dev uses **MySQL** (`five12_website`, creds in `backend/.env`). The desktop
   Electron app uses **SQLite**. Different databases, different data — always
   confirm which one you are looking at.
3. **The app launches its own backend.** So a model change without a matching
   migration breaks the app the moment it restarts, even if your own backend is
   fine. That is exactly how the subnets vanished at the end of this session:
   an `ignore_cidrs` column existed on the model for ~30 minutes with no
   migration, the app spawned a backend that loaded it, and every subnet query
   500'd until that process was killed.
4. After ANY backend code change: `Get-Process python` and kill survivors. A
   stale process reverts data silently rather than failing loudly. The tell is a
   HALF-updated row (new code writes one field, old code overwrites another).

Start the backend:

```powershell
cd backend
$env:FLASK_APP='app.py'
& .venv\Scripts\python.exe -m flask run --host=127.0.0.1 --port=5000 --no-reload
```

Tests: `& .venv\Scripts\python.exe -m pytest tests/ -q`

### 2. "Remove offline devices" button, per subnet

Operator intent: *"the red ones go away, but if it plugs back in it should have
all the same notes and labels applied to it."* So this is a **soft hide keyed on
MAC, never a delete.**

- Add `NetworkDevice.hidden` (bool, default false).
- `POST /api/network/subnets/<id>/clear-offline` sets `hidden=True` for offline
  devices in that subnet; returns the count. Label and notes are untouched.
- `GET /api/network/devices` filters hidden out by default.
- `_process_discovered_device` sets `hidden=False` on any sighting, so a device
  that comes back reappears with its label and notes intact.
- Offline threshold is **90s**, defined in `app/src/pages/NetworkMonitor.jsx:17`.
  The backend must match it or the button will not match what the UI shows red.
- UI: button per subnet, confirm dialog with the count.

## Open / unverified

1. **Five Netgears still need SNMP.** `.97` and `.98` are configured. Each
   unconfigured switch burns ~6s of retries per sweep, so the remaining five add
   ~30s to every Management pass. Community `public`, ReadOnly, restricted to
   `172.16.0.0/255.255.0.0`.
2. **scapy contributes nothing on this host.** `_scapy_scan` returns 0 answers
   without raising (no Npcap/admin) on every subnet — all real discovery comes
   from `arp -a` plus the ping warm-up. Worth making the active sweep opt-in
   rather than paying for it every pass.
3. **Better discovery than sweeping:** ask the switches. `ipNetToMediaTable`
   (`1.3.6.1.2.1.4.22.1.2`) is a device's own ARP table — one walk returns the
   whole VLAN's IP<->MAC map, including quiet devices that never answer a ping.
   `dot1qTpFdbPort` gives MAC->port for everything the switch has seen. This
   scales to a /8 trivially because you query ~7 switches, not 16.7M addresses.
4. **Enrichment failure is invisible.** `_process_discovered_device` only writes
   `vendor_data` when truthy, so a switch that stops answering SNMP silently
   keeps its last-known blob rather than clearing or flagging it.
5. **Unverified oddity:** two devices with the Luminex OUI `D0:69:9E` on
   `172.16.1.x` were typed `unknown` while six others typed `luminex`
   correctly. Not investigated. May just be stale rows from a pre-fix process.
6. `entPhysicalHardwareRev` is empty on Netgear hardware — HW VERSION will never
   populate for these switches. Do not re-investigate it.
